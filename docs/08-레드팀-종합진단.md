# 레드팀 종합 진단 · 새김AI (얼마루 종합컨텐츠제작소)

2026-10-11 (일) KST. 기준 커밋 `892d7d5`.

이 문서는 저장소 전체(프론트엔드 `src/`, 백엔드 `local-api/`, 운영 스크립트 `scripts/`, 문서 `docs/`)를
한 줄씩 읽고, 일부는 실제로 서버를 띄워 공격해 본 결과입니다.
각 항목에 **근거 수준**을 붙였습니다.

| 표시 | 뜻 |
|---|---|
| **실측** | 이 진단 중 서버를 띄워 직접 재현함 |
| **코드** | 코드 경로를 따라가 확인했으나 실제 환경(작업실 PC)에서 재현하지는 않음 |
| **추정** | 설계상 그럴 가능성이 높으나 확인하지 못함 |

번호 체계: 결함은 `R-nn`, 자동화 과제는 `A-nn`, 추가 기능은 `F-nn` 입니다. 이 문서 안에서만 쓰는 번호입니다.

## 0. 한눈에

| 구분 | 현재 | 가장 큰 구멍 |
|---|---|---|
| 공개 갤러리 (Vercel + 내 PC) | 잘 정돈됨. 경로 조작 방어·짧은 타임아웃·문 닫힘 화면까지 갖춤 | PC 한 대가 곧 서비스 전체. 백업 없음 |
| 만들기 콘솔 (studio) | 포트 분리, 상수 시간 비교 등 기본기 좋음 | 교차 사이트 요청(CSRF) 방어 없음, 무차별 대입 제한 없음 |
| 번역기 (/translator) | 브라우저 OCR + 서버 번역 프록시 | 번역 API 가 **누구에게나 열려 있음** (유료 키 남용 가능) |
| 자동화 | 자동시작·중복기동 방지 스크립트 있음 | CI·테스트·백업·감시 **전무**. 작품 공개는 CLI 5단계 수작업 |

**가장 먼저 할 일 5가지** (모두 반나절 이내 규모):

1. `R-01` 번역 API 에 속도 제한·길이 제한·출처 확인
2. `R-02` 콘솔 POST 에 `Origin` 검사 + `Content-Type: application/json` 강제
3. `R-05` SQLite `busy_timeout` 추가 (동시 기동 시 콘솔이 죽는 문제)
4. `R-06` 콘솔에서 건 그림을 `ingested` 표에도 기록 (중복 등록 방지)
5. `A-01` GitHub Actions 로 lint·타입검사·빌드 자동 검증

## 1. 구조

```
방문자 ─▶ saegimai.com (Vercel, Next.js 16)
            ├─ /             Atelier 갤러리 ── fetch ─▶ api.saegimai.com ─┐
            ├─ /work/[slug]                                              │ Cloudflare Tunnel
            ├─ /status                                                   ▼
            ├─ /translator   번역기 (브라우저 Tesseract OCR)       내 PC :8787 server.mjs (읽기 전용 API)
            └─ /api/translate ─▶ DeepL / MyMemory                     │  SQLite + media/
                                                                      │
나 ─▶ studio.saegimai.com ─ Tunnel ─▶ 내 PC :8788 studio-server.mjs ─┤
                                         (Basic 인증)                 └─ ComfyUI :8188 (로컬만)
```

코드 규모: TS/TSX 약 2,300줄, Node 백엔드 약 1,000줄, CSS 약 2,100줄. 외부 런타임 의존성은
`next`, `react`, `tesseract.js`, `pdfjs-dist`, `jszip` 뿐이고 백엔드는 Node 표준 라이브러리만 씁니다.
작은 규모에 비해 주석과 운영 문서가 매우 충실합니다. 이 점은 그대로 유지할 가치가 있습니다.

## 2. 레드팀 발견 사항

### 높음

#### R-01 · 번역 API 가 누구에게나 열려 있음 — 코드
`src/app/api/translate/route.ts`

- 인증·속도 제한·출처 확인이 없습니다. 아무나 `POST https://saegimai.com/api/translate` 를 반복 호출할 수 있습니다.
- 한 요청에 200줄까지 받지만 **줄당 길이 제한이 없습니다.** DeepL 은 글자 수로 과금되므로
  `DEEPL_API_KEY` 를 넣는 순간 남이 그 키로 번역을 돌려도 비용은 내가 냅니다.
- 키가 없으면 MyMemory 일일 한도가 남에게 소진되어, 정작 내 번역이 원문 그대로 돌아옵니다
  (오류 시 원문 반환 로직 때문에 **실패가 눈에 띄지 않습니다**).
- 외부 `fetch` 에 타임아웃이 없어 상대 서버가 느리면 Vercel 함수 시간을 그대로 씁니다.

**고칠 방향**: 줄당 500자·요청당 총 5,000자 상한 → `Origin`/`Sec-Fetch-Site` 확인 →
IP 별 속도 제한 (Upstash Ratelimit 같은 Redis 기반 슬라이딩 윈도가 Next.js 라우트에서 흔히 쓰는 방식) →
`AbortSignal.timeout(10_000)`.

#### R-02 · 만들기 콘솔에 교차 사이트 요청 방어가 없음 — 실측
`local-api/studio-server.mjs`

- `readBody()` 가 `Content-Type` 을 보지 않고 본문을 JSON 으로 파싱합니다.
- 실측: `Origin: https://evil.example`, `Content-Type: text/plain` 으로 `/api/generate`, `/api/publish`
  에 POST 하면 **인증만 맞으면 처리 단계까지 들어갑니다** (ComfyUI 호출 직전까지 도달 확인).
- `text/plain` 은 HTML `<form>` 이 보낼 수 있는 형식이라 사전 요청(preflight) 없이 나갈 수 있습니다.
- 시나리오: 콘솔에 로그인해 둔 브라우저로 악성 페이지를 열면, 그 페이지가
  ① 생성 작업을 줄 세우고 ② `/api/interrupt` 로 작업을 끊고 ③ `/api/publish` 로 ComfyUI
  출력 폴더의 아무 이미지나 **공개 갤러리에 걸 수 있습니다.**
- 단, 브라우저가 저장해 둔 Basic 인증 정보를 교차 사이트 요청에 실어 보내는지는 브라우저·설정마다
  다릅니다. **실제 브라우저에서 공격이 성립하는지는 검증하지 않았습니다(추정).** 방어 비용이
  몇 줄이므로 성립 여부와 무관하게 막는 편이 맞습니다.

**고칠 방향**: 상태를 바꾸는 모든 POST 에서 `Origin` 이 `studio.saegimai.com` 또는 `127.0.0.1:8788`
인지 확인하고, `Content-Type: application/json` 이 아니면 415 로 거절.

#### R-03 · 콘솔 로그인에 무차별 대입 제한이 없음 — 실측
- 틀린 비밀번호 30회 연속 → 30회 모두 즉시 401. 지연·잠금 없음.
- 비밀번호가 32자(문서 기준 약 210비트)라 실제로 뚫릴 가능성은 낮습니다.
  그러나 **아이디(이메일)가 `local-api/.env.example` 에 그대로 커밋되어 있어** 절반은 공개된 셈입니다.
- Basic 인증은 로그아웃이 없고, 비밀번호를 바꾸기 전까지 영구히 유효합니다.

**고칠 방향**: studio 앞에 **Cloudflare Access** (이메일 1회용 코드 또는 Google 로그인)를 둡니다.
Cloudflare 안내에 따르면 Zero Trust → Access → Applications → Self-hosted 로
`studio.saegimai.com` 을 등록하고 내 이메일만 허용하는 정책을 걸면 됩니다.
이렇게 하면 R-02·R-03 이 터널 앞단에서 함께 줄어듭니다. 서버의 Basic 인증은 2차 방어로 남겨 둡니다.
`.env.example` 의 실제 이메일은 `you@example.com` 같은 본보기 값으로 바꿉니다.

#### R-04 · 서비스 전체가 PC 한 대에 묶여 있고 백업이 없음 — 코드
- DB(`atelier.db`)와 원본 이미지(`media/`)가 PC 한 디스크에만 있습니다. 깃에도 올라가지 않습니다(의도된 설계).
  **디스크가 망가지면 갤러리 전체가 사라집니다.** 백업 스크립트나 문서가 저장소 어디에도 없습니다.
- 자동시작은 "로그인할 때" 만 동작합니다(`docs/06`). 정전·윈도우 업데이트 재부팅 뒤 로그인하기 전까지 사이트가 닫힙니다.
- 꺼졌을 때 알려 주는 장치가 없습니다. 방문자가 먼저 압니다.

**고칠 방향**: `A-04`(자동 백업), `A-05`(감시), `F-01`(R2 미러) 참고.

### 중간

#### R-05 · API 와 콘솔을 동시에 켜면 콘솔이 죽을 수 있음 — 실측
`local-api/db.mjs`

- 두 프로세스가 같은 SQLite 파일을 동시에 열면 `PRAGMA journal_mode = WAL` 단계에서
  `Error: database is locked` 로 한쪽이 종료됩니다. `busy_timeout` 이 설정되어 있지 않기 때문입니다.
- 실측: 새 DB 로 동시 기동 10회 중 **2회 크래시**, 이미 있는 DB 로는 10회 중 0회.
- `scripts/공방_열기.ps1` 이 정확히 이 순서(API·콘솔을 연달아 `Start-Process`)로 띄웁니다.
  최소화 창에서 죽으므로 알아채기 어렵습니다.
- 같은 원인으로 `ingest.mjs` 와 콘솔의 "갤러리에 걸기" 가 동시에 쓰면 쓰기 실패가 날 수 있습니다(추정).

**고칠 방향**: `new DatabaseSync(file, { timeout: 5000 })` 또는 `PRAGMA busy_timeout = 5000`
을 다른 PRAGMA 보다 먼저 실행. (Node 22 의 `node:sqlite` 옵션 이름은 적용 전에 Node 문서로 확인 필요)

#### R-06 · 콘솔에서 건 그림이 "새작품 등록" 때 숨김 상태로 한 번 더 들어감 — 코드
- 콘솔은 ComfyUI 에 `filename_prefix: 'atelier/studio'` 로 저장시킵니다 → `ComfyUI/output/atelier/studio_xxxxx_.png`.
- `publish()` 는 `works` 에만 넣고 `ingested` 표에는 기록하지 않습니다.
- `ingest.mjs` 는 `ATELIER_SOURCE`(= `ComfyUI/output`) 를 **하위 폴더까지** 훑고 `ingested` 로만 중복을 거릅니다.
- 따라서 `새작품_등록.bat` 을 누르면 콘솔에서 이미 건 그림(과 걸지 않은 시안 전부)이 숨김 작품으로 다시 등록되고
  `media/` 에 사본이 하나 더 생깁니다. 실제 PC 에서 재현하지는 않았습니다.

**고칠 방향**: `publish()` 에서 원본 경로를 `ingested` 에 기록. 더 근본적으로는 파일 경로가 아니라
**내용 해시(SHA-256)** 로 중복을 판단 (파일을 옮기거나 이름을 바꿔도 안전).

#### R-07 · 보안 헤더 부재와 내부 오류 노출 — 실측
- 콘솔 응답에 `X-Frame-Options`/`Content-Security-Policy` 가 없어 다른 사이트가 콘솔을 `<iframe>` 으로 감싸
  클릭을 유도할 수 있습니다(클릭재킹).
- 콘솔 500 응답이 예외 메시지를 그대로 돌려줍니다 (`"fetch failed"`, ComfyUI 응답 본문 300자 등).
- 공개 API(8787)·Vercel 쪽도 `X-Content-Type-Options`, `Referrer-Policy` 등을 설정하지 않습니다.

**고칠 방향**: 콘솔 모든 응답에 `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`, 간단한 CSP. Vercel 쪽은 `next.config.ts` 의 `headers()`.

#### R-08 · 번역기에서 일본어·중국어 번역문이 줄바꿈되지 않음 — 코드
`src/lib/compose.ts` `wrapText()`

- 공백(`\s+`)으로만 줄을 나눕니다. 번역 결과가 일본어·중국어(대상 언어 `ja`/`zh`)면 공백이 거의 없어
  문장 전체가 한 "단어" 가 되고, `fitText()` 가 글자 크기를 최소 8px 까지 줄인 뒤에도 넘치면 그대로 그립니다.
- 한국어·영어 대상에서는 문제가 덜합니다.

**고칠 방향**: `Intl.Segmenter`(granularity `grapheme` 또는 `word`) 로 나누고, CJK 는 글자 단위 줄바꿈 허용.

#### R-09 · OCR 이 페이지마다 엔진을 새로 띄우고 6개 언어를 한꺼번에 읽음 — 코드
`src/lib/ocr.ts`, `src/lib/pipeline.ts`

- `runOcr()` 가 호출될 때마다 `createWorker()` → `terminate()`. 폴더 일괄 처리에서 페이지 수만큼 엔진 초기화가 반복됩니다.
- "다국어 자동 인식"(기본값 켜짐)은 `jpn+kor+chi_sim+eng+vie+tha` 를 한 번에 올립니다.
  언어팩을 많이 섞을수록 느리고 오인식이 늘어나는 경향이 있습니다(추정, 측정 안 함).
- 일본 만화의 **세로쓰기**(`jpn_vert`)를 다루지 않습니다. 원문 만화 대다수가 세로쓰기입니다.
- 줄 단위로 번역 API 에 보내 **말풍선 안 문장이 줄마다 잘린 채** 번역됩니다. 문맥 손실이 큽니다.

**고칠 방향**: 워커 1개(또는 `createScheduler` 로 2~4개) 재사용 · 말풍선 단위로 줄을 합쳐 번역 · `F-05` 참고.

#### R-10 · PC 가 꺼졌을 때 첫 화면이 몇 초 늦게 뜰 수 있음 — 코드(추정 포함)
- 매 방문마다 `/health`(3초 제한)를 확인합니다(`force-dynamic`). 터널은 살아 있고 PC 만 꺼진 경우
  최대 3초를 기다린 뒤 "문 닫힘" 을 보여 줍니다.
- `/work/[slug]` 는 `generateMetadata` 가 `isOnline()` 확인 없이 `getWork()`(4초 제한)를 먼저 부르므로
  최악의 경우 더 길어질 수 있습니다. 실제 지연은 측정하지 않았습니다.
- 작품 페이지는 "총 몇 점" 하나를 보이려고 목록 120개를 통째로 받아옵니다.

**고칠 방향**: `/health` 결과를 10~15초 캐시 · 작품 수는 `/api/site` 응답에 포함 · `F-01` 로 근본 해결.

### 잘 되어 있는 것 (유지)

- 미디어 파일명 화이트리스트 + `basename` 비교로 **경로 조작 차단** — 실측으로 `..%2F` 시도가 400.
- 공개 API 는 GET/HEAD 만, CORS 허용 목록 방식.
- 콘솔을 **별도 포트**로 분리해 공개 터널 호스트에서 닿지 않게 한 설계.
- `timingSafeEqual` 로 비밀번호 비교, 요청 본문 64KB 제한, 입력값 범위 고정(steps·cfg·batch).
- PC 가 꺼져도 사이트가 "깨진" 게 아니라 "문 닫힘" 으로 보이게 한 처리, 모든 외부 호출의 짧은 타임아웃.
- 운영 문서(`docs/00~07`)가 날짜·확인 결과까지 남겨 둔 점.

## 4. 추가해야 할 부분 — 벤치마킹

### 4-1. 번역기: 오픈소스 만화 번역기와의 차이

비교 대상은 공개 저장소 설명과 2차 요약을 근거로 했습니다. 각 프로젝트의 **현재 기본값·라이선스는 직접 확인하지 않았습니다.**

| 단계 | 우리 | manga-image-translator | BallonsTranslator | comic-translate |
|---|---|---|---|---|
| 글자 영역 찾기 | 밝은 영역 flood-fill 휴리스틱 | 학습 모델(`ctd` 등) | 학습 모델 | 학습 모델 |
| 글자 읽기 | Tesseract (범용 문서용) | 만화 특화 OCR | mit 32/48px, manga-ocr(일본어) | manga-ocr 등 |
| 원문 지우기 | 배경색 사각형 덮기 | LaMa 인페인팅(`lama_large`) | 인페인팅 | 인페인팅 |
| 번역 | 줄 단위 MyMemory/DeepL | 여러 번역기·LLM 선택 | 여러 번역기 | LLM 중심 |
| 조판 | 가로쓰기, 사각 상자 | 말풍선 맞춤 | 말풍선 맞춤 + **수동 편집 UI** | 말풍선 맞춤 + 편집 |

연구 근거: COLING 2025 「Context-Informed Machine Translation of Manga」 는 LLM 에 앞뒤 대사·몇 개의 예시를
문맥으로 주면 만화 번역 품질이 오른다고 보고합니다. 우리 구조는 줄마다 끊어 보내므로 이 이점을 전혀 못 얻습니다.

| 번호 | 추가할 것 | 이유 |
|---|---|---|
| F-05 | **말풍선·페이지 단위 LLM 번역** (Claude API, 앞 페이지 대사·용어집·등장인물 이름표를 문맥으로) | 가장 적은 코드로 가장 큰 품질 향상. 번역 라우트 하나만 바꾸면 됨 |
| F-06 | 번역 결과 **수동 교정 화면** (줄 클릭 → 수정 → 다시 그리기) | 경쟁 도구 공통 기능. 자동 결과는 반드시 틀린 곳이 있음 |
| F-07 | 작업실 GPU 를 쓰는 **로컬 번역 워커** (감지 모델 + manga-ocr + LaMa) 를 studio 옆 포트에 | 브라우저 Tesseract 로는 품질 상한이 뚜렷함. 이미 GPU PC 와 터널 구조가 있으므로 확장이 자연스러움. 단 GTX 1660 Ti 6GB 에서 ComfyUI 와 동시 구동 시 VRAM 이 부족할 수 있음(추정) |
| F-08 | 세로쓰기(`jpn_vert`) 인식·조판 | 일본 만화 원문 대응 |
| F-09 | 용어집(고유명사 고정) | 시리즈 번역 일관성 |
