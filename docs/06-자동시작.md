# 컴퓨터 켤 때 자동으로 열리게

2026-08-29 (토) 10:50 KST 설정 완료.

## 지금 어떻게 되어 있나

이 컴퓨터에 **로그인할 때마다** 로컬 API 와 Cloudflare 터널이 자동으로 켜집니다.
창 두 개가 작업표시줄에 **최소화된 채로** 뜹니다.

| 항목 | 값 |
|---|---|
| 등록 위치 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\새김AI 공방 열기.lnk` |
| 실행하는 것 | `scripts\공방_열기.ps1` |
| 창 모양 | 최소화 |

`cloudflared service install` 은 **쓰지 않았습니다.** 관리자 권한이 필요한데
이 계정에는 없습니다. 시작프로그램 방식은 관리자 권한이 필요 없고,
로그인한 사용자로 도는 대신 **로그인해야** 켜진다는 차이가 있습니다.

## 켜고 끄기

| 하고 싶은 것 | 하는 법 |
|---|---|
| 지금 켜기 | `scripts\공방_열기.bat` 두 번 누르기 |
| 지금 끄기 | 최소화된 창 두 개 닫기 |
| 자동시작 켜기 | `scripts\자동시작_켜기.bat` |
| 자동시작 끄기 | `scripts\자동시작_끄기.bat` |

`공방_열기` 는 이미 떠 있으면 다시 띄우지 않습니다. 두 번 눌러도 안전합니다.

## 확인한 것

두 프로세스를 강제로 죽인 뒤 `공방_열기.ps1` 을 실행해,
로컬 API 와 터널이 되살아나고 `https://api.saegimai.com/health` 가
바깥에서 200 을 돌려주는 것까지 확인했습니다.

## 주의 — DNS 캐시에 속지 마십시오

DNS 를 바꾼 직후, **이 컴퓨터에서만** 사이트가 안 열리는 일이 있습니다.
옛 주소가 캐시에 남아 옛 서버로 붙기 때문입니다.
증상은 `SEC_E_WRONG_PRINCIPAL` (인증서 이름 불일치) 입니다.

실제로 2026-08-29 에 이 함정에 걸렸습니다.
`www` 가 안 열려 인증서 발급이 안 된 줄 알았는데,
알고 보니 이 PC 가 옛 서버(`157.230.252.194`, Cloudways)로 붙고 있었습니다.
그쪽이 내놓는 `*.cloudwaysapps.com` 인증서가 이름과 안 맞아 연결이 끊긴 것입니다.

해결:

```powershell
Clear-DnsClientCache
ipconfig /flushdns
```

사이트가 진짜 살아 있는지는 이렇게 확인합니다:

```bash
curl -s --resolve saegimai.com:443:216.150.1.1 https://saegimai.com/ -o /dev/null -w "%{http_code}\n"
```
